# Data Dictionary

## Purpose

This data dictionary documents the raw/source fields and derived cleaning, validation, and analytical fields present in the cleaned Track 2 datasets.

The dictionary reflects the actual schemas generated by the cleaning pipeline.

### Field conventions

- `*_raw` = original source value preserved for traceability.
- `*_clean` = standardized/validated analytical value.
- `*_valid` = validation result for the corresponding field.
- `*_status` = semantic status of a cleaned value.
- `*_issue` / `*_reason` = explanation of a detected data-quality issue.
- `*_rank` = analytical ranking derived from a standardized categorical value.

# 5. Cross-Dataset Join Keys

The cleaned datasets use the following integration keys:

| Relationship | Join Key | Purpose |
|---|---|---|
| IAM → Identity | `user_id_clean` | Link authentication/access events to employee identity |
| Endpoint → Identity | `user_id_clean` | Link endpoint alerts to employee identity |
| Endpoint → Identity | `hostname_clean` | Link endpoint alerts to employee/device master |
| Firewall → Identity | canonical hostname | Link network activity to employee/device master |
| IAM → Firewall | `session_id` | Identify possible cross-telemetry sessions |

## Join-key normalization

User IDs and hostnames are normalized before integration checks.

Hostname normalization includes:

- trimming whitespace
- uppercase conversion
- `_` converted to `-`
- `.corp.local` suffix removed

No synthetic identity records are created to resolve unmatched telemetry records.

# 6. Data Quality and Traceability Fields

The cleaned datasets intentionally contain raw and derived fields together where required for auditability.

### Raw fields

Fields ending in `_raw` preserve the original source representation.

### Clean fields

Fields ending in `_clean` contain the standardized or validated analytical representation.

### Validation fields

Fields ending in `_valid` identify whether the associated value passed validation.

### Issue fields

Fields ending in `_issue` or `_reason` describe detected data-quality problems.

This structure allows downstream analytics to use the cleaned values while retaining the ability to investigate the original source values.
